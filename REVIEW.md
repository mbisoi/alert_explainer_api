# Alert Explainer Scaffold Review

## Validation

The API was exercised using FastAPI TestClient and an isolated in-memory SQLite
database. No Uvicorn server was started and no sample alerts were persisted.
Importing the app created the empty local `alerts.db` file as intended.

Verified:

- Both sample POST requests return 201, IDs, submitted fields, and UTC timestamps.
- Listing and retrieving alerts return the expected fields.
- Both sample explanations match the lab strings exactly.
- Above, below, and equal comparisons work for all three severities.
- Unknown IDs return 404 with `{"detail": "Alert not found"}` on both routes.
- Invalid severities return 422.
- The database dependency closes its session on success and exceptions.
- `/docs` responds and OpenAPI describes exactly the four alert operations.

This verifies the docs response and schema, not browser rendering of Swagger UI.
HTTPX was installed in the virtual environment only for these checks; it is not
a runtime requirement. The installed Starlette emitted a deprecation warning
about its HTTPX TestClient integration, but all checks passed.

### services/explainer.py

| Line | What it does and why |
| --- | --- |
| `from models import Alert` | Imports the ORM type for the function's annotation; no database query happens here. |
| `def generate_explanation(alert: Alert) -> str:` | Defines a deterministic formatter taking one alert and returning text. |
| `if alert.metric_value > alert.threshold:` | Tests whether the observed value is above the threshold. |
| `comparison = "exceeded"` | Selects the required above-threshold wording. |
| `elif alert.metric_value < alert.threshold:` | Checks the below-threshold case when the first test is false. |
| `comparison = "fell below"` | Selects the required below-threshold wording. |
| `else:` | Handles equality for ordinary finite numbers. |
| `comparison = "reached"` | Selects the required equality wording. |
| `next_steps = {` | Begins a severity-to-recommendation lookup table. |
| `"critical": "Investigate immediately and take corrective action.",` | Sets the exact critical recommendation. |
| `"warning": "Review the affected system and monitor the metric closely.",` | Sets the exact warning recommendation. |
| `"info": "Review the metric and confirm whether any action is needed.",` | Sets the exact informational recommendation. |
| `}` | Completes the lookup table. |
| `return (` | Begins the returned string, split across lines for readability. |
| `f'This {alert.severity} alert from {alert.source} is titled "{alert.title}". '` | Includes this alert's severity, source, and quoted title; trailing space separates sentences. |
| `f"The {alert.metric_name} metric {comparison} its threshold: "` | Names this alert's metric and the computed comparison. |
| `f"the current value is {alert.metric_value}, "` | Includes this alert's observed value. |
| `f"compared with a threshold of {alert.threshold}. "` | Includes this alert's threshold and ends the sentence. |
| `f"Recommended next step: {next_steps[alert.severity]}"` | Appends the severity-specific recommendation without adding extra punctuation. |
| `)` | Completes the return expression; Python concatenates these adjacent formatted strings. |

The function reads only the supplied alert and fixed recommendations. There is
no network client, external AI call, database query, or mutation in the function.

## Risks And Limits

- This is a local lab scaffold, not a production-ready monitoring service:
  there is no authentication, authorization, rate limiting, or pagination.
- Recommendations are generic rules, not diagnosis or verified corrective advice.
- Text fields accept empty and arbitrary strings. Responses are plain JSON;
  clients must escape them when rendering HTML and avoid leaking sensitive data.
- Numeric fields are not restricted to finite values. Nonfinite Python floats
  can cause misleading comparisons or JSON serialization failures.
- Direct database writes can bypass severity validation and cause a KeyError
  in the recommendation lookup. Add a database constraint for broader usage.
- UTC restoration assumes timestamps were originally written in UTC; manually
  inserted local times would be mislabeled.
- SQLite suits this lab, but write contention becomes a concern under load.
- `create_all()` is convenient for setup, not schema migration management.
- Dependency versions are intentionally unpinned to match the requested list;
  use tested version constraints or a lockfile for reproducible deployments.

## Running Later

The server was deliberately not started, following the scaffold instruction.
From an activated virtual environment, run `uvicorn main:app --reload` when
ready for the manual lab, then visit `http://127.0.0.1:8000/docs`.
The on-disk database is empty, so the two manual inserts can obtain IDs 1 and 2.
Use Ctrl+C to stop the server. Do not expose the reload server publicly.
